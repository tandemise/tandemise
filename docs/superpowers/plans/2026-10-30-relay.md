# Relay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A team can run an optional, self-hosted relay with `docker compose up` that tells every connected daemon who is working on which tracker item, manages members and device tokens, and holds raw webhooks for a daemon to pull. Solo use keeps working with the same `coord_*` tables in the daemon's own database.

**Architecture:**
- One schema and one rule set live in a new layer-3 package, `@tandemise/coordination`. It holds the `coord_*` DDL, `CoordinationStore` over a minimal `SqlHandle`, `itemRef` normalisation, and the claim, take-over, mailbox and retention rules as pure functions. It also holds `LocalCoordination`, the solo implementation.
- The wire types live in `@tandemise/api-contract/relay`, a subpath that imports only `zod` at runtime.
- `apps/relay` is a `node:http` + `ws` + `better-sqlite3` server that imports only those two internal modules.
- `@tandemise/coordination-relay` (layer 4, provider) is the daemon's client. It keeps a mirror and an outbox in the daemon's `coord_*` tables.
- The application sees one `CoordinationPort` (token `COORDINATION`). It claims an issue-linked mission's tracker item before the mission starts, and releases it when the mission ends. A lost claim never stops work: the mission becomes Unclaimed and the person decides.
- The desktop talks only to the daemon (`/v1/coordination/*`).

**Tech Stack:** TypeScript, Node 22, `better-sqlite3` (already used by persistence), `ws@^8` (already used by the daemon), `zod`, React 18, Electron 44, Docker (`node:22-bookworm-slim`), Caddy (optional `tls` profile).

**Spec:** `docs/superpowers/specs/2026-10-30-relay-design.md`. It is binding; read it first. This plan argues from it and only pins what the spec left open.

## Global Constraints

- **Migrations (coordination ruling).**
  - The relay's own database runs `COORDINATION_MIGRATIONS` from `@tandemise/coordination`, numbered from `001`, with the version recorded in `coord_meta.schema_version`.
  - The daemon's database gets the same tables through persistence migration **025** (`025_coordination.ts`). Hold-and-interact owns 022, brain owns 023 and intake owns 024.
  - Persistence (L2) can't import coordination (L3), so 025 carries the DDL text verbatim. A parity assertion in `coordination-check` keeps them identical (Task 4).
  - The daemon also calls `migrateCoordination(db.handle)` at boot. After 025 that is a no-op, and it runs any later coordination migrations.
  - `assertOrdered` requires a contiguous list. If 022–024 are not on `main` when Task 4 starts, wait and rebase. Never renumber.
- Layer rules hold (`npm run check:boundaries`):
  - `coordination` is L3. It depends only on `api-contract`, and never imports `better-sqlite3`.
  - `coordination-relay` is L4 and is in `PROVIDER_PACKAGES`.
  - `apps/relay/src` may import only `@tandemise/api-contract/relay`, `@tandemise/coordination`, `ws`, `better-sqlite3`, `zod` (through the contract) and `node:*`.
  - The renderer imports `@tandemise/*` as types only.
- **Edits to shared files stay minimal and additive.** Another feature is changing `packages/application/src/tokens.ts`, `task-executor.ts` and the desktop `TaskDetail.tsx` at the same time.
  - Add one token line to `tokens.ts`.
  - Never touch `task-executor.ts` or `TaskDetail.tsx`.
  - In `mission-service.ts` and `approval-service.ts`, add one optional dep and one awaited call each.
- **The relay never stops work.** No code path from a claim ending (`taken_over`, `removed`, conflicted) may cancel, pause or block a mission. Reads (`claims`, `members`, `presence`) are synchronous from local tables and never touch the network.
- **Offline never blocks local work.** A claim made while the relay is unreachable returns `queued_offline` and the mission starts.
- **Secrets.** The relay stores only SHA-256 hashes of tokens and invite codes. The daemon keeps the device token in `SecretStorePort`, and the settings file holds only its reference. There is no `?token=` fallback on the relay. Webhook bodies and headers are never logged.
- **Errors.** Use the daemon's `ApiErrorBody` envelope with existing `ErrorCode`s; relay-specific causes go in `details.reason`. The UI shows the daemon's own words.
- **UI copy.** It says "you", uses plain verbs, and never shows raw enums. Colours come only from `palette.css`/`theme.css`, with no `var()` fallbacks; BEM classes; state in `data-*`.
- **Repo rules.** Repo artifacts are in English. PR titles are Conventional Commits with a lowercase subject. Run `npm run ci` before each PR. Do not use `scripts/scaffold.mjs`, because it overwrites every `package.json`.

## Review Focus

1. **Two claims racing for one item.** The partial unique index is the only arbiter. A `SQLITE_CONSTRAINT_UNIQUE` must become `409 CONFLICT` with `details.reason:"claim_held"` and the holder's claim, never a 500. Pinned in Tasks 2 and 8.
2. **Offline reconciliation.** The outbox drains in order. A claim that loses on reconnect becomes `conflicted`, its mission keeps running, and it shows Unclaimed with the winner's name and time. Pinned in Task 11.
3. **The relay never stops work.** A take-over or a member removal marks the mission Unclaimed and records an Inbox row, but its tasks keep their statuses. Pinned in Task 5.
4. **Mailbox leases.** A message is delivered to one device at a time. Only the lease holder may ack it, an expired lease re-leases, and the tenth unacked lease parks the message. Pinned in Tasks 3 and 9.
5. **Auth and exposure.** The device token is only ever sent in a header. A revoked device's socket closes at once. Unknown and disabled slugs answer identical 404s. The daemon gains no inbound listener. Pinned in Tasks 8–11.

It drops hop-by-hop headers (`connection`, `keep-alive`, `transfer-encoding`, `upgrade`, `te`, `trailer`, `proxy-*`), `cookie` and `authorization`, and keeps everything else, including `sentry-hook-signature` and `x-hub-signature-256`.

    - **`meta_hub`:** on a GET with `hub.mode=subscribe`, it returns `200` and the challenge when the verify token matches, and `403` with `''` when it doesn't.
    - **`echo_challenge`:** a JSON body `{type:'url_verification',challenge}` returns `200` with the challenge.
    - Otherwise it returns `null`.
  - `store.storeRequest(endpointId, req: { method; query; headers; contentType; body: Buffer }): { id: string }`. It enforces the caps with `enforceCaps`, which drops the oldest unacked message, increments `dropped_count` and sets `drop_flag`.
  - `store.pull(projectKey, deviceId, max, leaseSeconds): MailboxMessage[]`
    - It leases messages in `id` order where `acked_at IS NULL AND parked_at IS NULL AND (lease_until IS NULL OR lease_until < now)`, and sets `lease_device`, `lease_until` and `attempts += 1`.
    - A row that would reach `attempts > PARK_AFTER_ATTEMPTS` is parked instead of leased.
  - `store.ack(ids, deviceId): { acked: string[]; ignored: string[] }`
    - It acks only rows whose `lease_device = deviceId` and `lease_until >= now`.
    - Acking clears `body`, sets `body_bytes = 0` and records `acked_at` and `acked_by`.
    - An expired or foreign lease is `ignored`, with no error, as the spec's offline table says.
  - `store.retryParked(id)` sets `parked_at = NULL, attempts = 0`. `store.dropParked(id)` deletes the row.
  - `sweep(store, policy: RetentionPolicy, now): { deletedAcked; expiredUnacked }`
  - `exportLines(store): string[]` writes the meta line first, with `schemaVersion`. `importLines(store, lines, mode: 'empty' | 'own-claims', actor): ImportReport`.
    - `'empty'` throws `relay_not_empty` unless `isEmpty()`, and is all or nothing in one transaction.
    - `'own-claims'` replays only claim lines through `claim()`.
    - It returns the contract's `ImportReport` (Task 1).
  - **`class LocalCoordination`** (`local.ts`) implements the application's `CoordinationPort` structurally (Task 5):
    - `constructor(store: CoordinationStore, me: { displayName: string; deviceLabel: string })`.
    - On construction it ensures the team, one admin member mirroring the local person, and one device.
    - `mode = 'local'`, `status()` → `{ kind:'local' }`.
    - `claim` maps `held` to `held_by`.
    - `onChange` is backed by an in-process listener set.

**Interfaces:**
- Consumes: the contract, the store and the `SqlHandle` of the daemon DB, plus `coord_outbox` and `coord_claim_sync` (Task 4).
- Produces:
  - **`RelayClient`**: `constructor({ baseUrl, token: () => Promise<string>, fetch = globalThis.fetch })`, with typed methods per route. Every request sets `Authorization` and `x-tandemise-relay-api: 1`, and a non-2xx answer becomes a `RelayHttpError { status; body: ApiErrorBody }`.
  - **`RelayStream`**:
    - It opens the global `WebSocket(url, { headers: { Authorization, 'x-tandemise-relay-api': '1' } })`. If the relay-check shows the header doesn't reach the server on Node 22, use the `ws` package (already a repo dependency) instead. Never put the token in the query.
    - It pings every 20 s and backs off 1 s → 5 min on close.
    - `onFrame`, plus a `gap` detection that triggers a snapshot.
  - **`Mirror`**:
    - `applySnapshot(s: RelaySnapshot)` replaces the members, presence and active claims of watched projects in `coord_*`. It keeps provisional rows and sets the sync to `confirmed`.
    - `applyFrame(f)` skips frames with `seq <= lastSeq`, and calls `resync()` on a gap.
    - When an own claim ends `taken_over`/`removed`, it sets `coord_claim_sync.sync = 'lost'` with the note sentence and fires `onChange('claims')`.
  - **`Outbox`**:
    - `enqueue(op: 'claim'|'release'|'take_over'|'ack', payload)`, and `drain(client): Promise<void>`, which drains in `id` order.
    - On `claim_held` it marks the claim `conflicted` with `"<holder> started <key> at <HH:MM>, while you were offline."` and continues.
    - Retryable errors (network, 5xx, 429) stop the drain and set `next_at` (1 s doubling to 300 s).
    - A non-retryable error (4xx other than 409/429) sets `failed_at` and moves on.
    - `failures(): { id; op; lastError }[]` feeds Settings.
  - **`RelayCoordination`** implements `CoordinationPort`, with `mode = 'relay'`:
    - Writes go to the relay first. On a network error they go to the outbox and a provisional mirror row with sync `pending`, and `claim` returns `queued_offline`.
    - `status()` is:

      | Situation | Status |
      |---|---|
      | stream open | `connected` |
      | after the first failure | `offline(since, pendingOps)` |
      | `401`/`412` | `refused(<daemon's sentence>)` |

    - `presence` frames are sent from `SwitchableCoordination.reportPresence`.
  - **Connect flow**:
    - It refuses a non-loopback `http://` URL unless `allowInsecure`, with `"This relay address isn't encrypted. Use https://, or tick \"I understand this is unencrypted\"."`.
    - Then: redeem the invite, store the token with `SecretStorePort.store('coordination.relay', token)`, write the settings and set `people.handles.relay = <host>/<memberId>`, swap, snapshot, open the stream.
  - **`importLocal`**: when `isEmpty`-equivalent (`snapshot.claims` is empty and there is one member) and you're admin, `POST /import` with `exportLines(localStore)`. Otherwise, the own active claims go through `claim`. It returns an `ImportReport`.
  - **`disconnect`**:
    - It closes the stream and swaps back to `LocalCoordination`.
    - Own active claims become local claims. Other mirror rows stay, with `coord_claim_sync.note = 'Last seen from the relay.'`.
    - It removes the secret and sets settings `mode: 'local'`.
